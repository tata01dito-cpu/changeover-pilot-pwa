# DATABASE SCHEMA (as of Chunk 16, part A)

No database yet. Only key-value storage (`localStorage`, prefix `eca-pilot:`, envelope `{v:1, t:ISO time, d:data}`).

| Key | Content | Chunk |
|---|---|---|
| disclaimer acknowledgement (`DISCLAIMER_KEY`) | `{version, acknowledgedAt}` | 00 |
| settings keys used by Settings screen | see `src/screens/Settings.tsx` | 00 |
| `vessel-profile` | `ProfileEnvelope` below | 01 |

No new storage keys in Chunks 03, 04, 05, 06, 07 or 12. Chunk 12 (alerts): NO storage key; the lead times, the notification list (acknowledgements included) and the latest evaluation are in memory only and are empty after a reload. GPS fixes, the GPS state, thresholds and the mock position are in memory only (nothing about position is stored; no history). Map layer choices, the DEMO toggle and the developer mock position are in-memory only (not persisted). Regulation datasets are bundled/in-memory only (import and persistence come in Chunk 11).

### Regulation dataset format (schemaVersion 3, versions 1 and 2 still accepted; not stored yet)
`{ schemaVersion: 1, datasetId, version, publicationDate, isDemo, records[] }`; no other top-level fields are accepted.
Record: `id, title, authority, document, reference, applicability, effectiveDate, expiryDate|null, sourceUrl (http/https), publicationDate, lastVerifiedDate, datasetVersion (must equal dataset version), timeState (CURRENT|FUTURE|EXPIRED|REPLACED|SUSPENDED|UNVERIFIED|STALE), isDemo (must equal dataset isDemo)`. Dates are ISO yyyy-mm-dd. `expiryDate` = first day the record no longer applies (convention, to confirm). Unknown fields, duplicate ids and DEMO/production mixing cause rejection.
Time-state rules: CURRENT needs effective ≤ today and no passed expiry; FUTURE needs effective > today; EXPIRED needs an expiry ≤ today; the other states are not date-derived.

### Sulphur block (schemaVersion 2, optional per record)
`"sulphur": { "limitPercentMm": number, "basis": "AREA" | "GLOBAL" | "PORT", "areaId": string | null }`. Strict: `limitPercentMm` finite, > 0 and <= 100, no default, no other fields. `GLOBAL` needs `areaId: null`; `AREA` and `PORT` need an area id. In a DEMO dataset the area id must start with `DEMO-`, in a production dataset it must not. Not allowed in a schemaVersion 1 dataset. Migration 1 -> 2: add `"schemaVersion": 2` and, where wanted, the block; nothing else changes. The value must be copied from the record's source document; the app never supplies one.

### NOx / PM blocks (schemaVersion 3, optional per record)
`"nox": { "basis": "AREA" | "GLOBAL" | "PORT", "areaId": string | null, "summary": string }` and the same shape for `"pm"`. `summary` is free text copied from the source (non-empty after trimming, at most 2000 characters); there is no numeric field and no default. Same area rules as the sulphur block (`GLOBAL` needs `areaId: null`; `AREA` and `PORT` need an area id; DEMO / production id prefixes are never mixed). No other fields. Not allowed in a schemaVersion 1 or 2 dataset (rejected as unknown field). A record may carry any combination of `sulphur`, `nox` and `pm`. Migration 1 -> 2 -> 3: add the blocks to records that carry them and raise `schemaVersion`; nothing else changes. UNCONFIRMED PROPOSAL (Settings).

### Area (geometry) format (strict parser input; imported area files are stored as AREAS versions since Chunk 16, see "Area boundary files" below)
`{ id, name, type, isDemo, geometry: { type: "Polygon" | "MultiPolygon", coordinates } }`, GeoJSON positions `[lon, lat]` in decimal degrees (WGS84), lat -90..90, lon -180..180. Rings must be closed, have >= 4 points and not self-intersect; holes must lie inside the outer ring. Antimeridian-crossing rings are written with the normal [-180, 180] longitudes (e.g. 170 then -170 means the short way across 180). `type` is a free label with no regulatory meaning. DEMO areas: `isDemo: true` and id starting `DEMO-`; production areas must not use that prefix. Unknown fields and duplicate ids are rejected. Persistence and import come with Chunk 11; planned table `eca_areas`.

### GPS fix (in memory only; NOT stored)
`GpsFix = { lat, lon, accuracyM|null, speedMps|null, headingDeg|null, timestamp (epoch ms), source: "device" | "mock" }`. `null` = not reported (never 0). `GpsState` adds reliability, quality, age, motion (SOG kn / COG deg with DERIVED flags and notes), message, error and notice. If position history is stored later (Chunk 13), planned table `gps_track` (fix columns + source); mock fixes must never be written to a real log.

### Prediction inputs and results (in memory only; NOT stored)
`PredictionInputs = { fobas: FobasInput|null, marginText, marginMinutes: number|null, useDemo }` lives in a session store (`services/prediction/inputsStore.ts`). The vessel profile holds fuel quantity and consumption but NOT sulphur values, so sulphur values and the safety margin are typed on the Changeover screen each app session. `PredictionResult` (OK or REFUSED with reason codes) is recomputed from the GPS state every second and never saved. Planned (Chunk 13): `changeover_log` may record a start time, but only real device fixes; MOCK and DEMO results must never be written to a real log.

### `vessel-profile` (inside the store envelope `{v:1,t,d}`)
`d = { schemaVersion: 1, savedAt: ISO time, profile: VesselProfile }`
- `vessel`: name, imoNumber (as typed), flag, vesselType, buildDate (YYYY-MM-DD or ""), company, notes
- `mainEngine`: EngineProfile = id, manufacturer, model, ratedPowerKw (kW, number|null), ratedRpm (rpm, number|null), shipConstructionDate, installationInfo, noxTier (tier_1|tier_2|tier_3|not_applicable|unknown|""), eiapp / technicalFile (held|not_held|not_applicable|unknown|""), scr / egr (fitted|not_fitted|unknown|""), approvedAlternative (approved|none|not_applicable|unknown|"")
- `auxiliaryEngines[]`: EngineProfile + label
- `noAuxiliaryEngines`: boolean (explicit confirmation of no aux engines)
- `fuel`: serviceSystemQuantity {value, unit m3|L|t|kg}, arrangement (common|separate|other), tanks[] {id, name, grade hfo|vlsfo|mgo|other, capacityM3}, consumption {value, unit t/h|kg/h|m3/h|L/h|t/day|m3/day}, notes
- `""` / `null` mean "not entered" and are never defaulted. Loading rejects (does not repair) wrong types, unknown enum values and unsupported schemaVersion.

Planned tables (not created): vessel, engines, fuel_profile (Chunk 01); regulations, eca_areas, port_regulations, sources, dataset_versions (Chunk 03); changeover_log, audit_trail (Chunk 13).
Regulation records must carry: authority, document, reference, effective date, applicability, source URL, publication date, last verified date, dataset version, time-state.

## Port list (Chunk 10 format; the bundled DEMO list is not persisted, an imported list is stored as an imported version, Chunk 11)
Own validated format, separate from the regulation datasets. Top level: `{ schemaVersion: 1, listId, version, publicationDate, isDemo, ports: [...] }` (unknown top-level fields reject the whole list; unsupported / missing schema version rejects the whole list).
Port: `{ id, name, unlocode | null, latitude, longitude, areaId | null, sourceUrl, lastVerifiedDate, isDemo }`. Every field is required (`null` is written explicitly for "none"). Rules: coordinates are finite degrees (lat -90..90, lon -180..180, and not 0, 0); ids are unique; `unlocode` is null or 5 characters (2 capital letters + 3 capital letters / digits 2-9, shape only, no code table) and is always null on a DEMO port; `sourceUrl` is http(s); `lastVerifiedDate` is a real date not in the future; `isDemo` must equal the list's flag; DEMO ids and DEMO area ids start with `DEMO-` and production ones never do. A port that fails is rejected with its issues and never repaired.
Link to regulations: a `sulphur` / `nox` / `pm` block with basis `PORT` names a port id in its `areaId` field. The regulation schema is unchanged (still version 3). Nothing is stored in the key-value store; port selection is session-only (10B).
No new storage key in Chunk 10. The chosen port id is held in memory for the session only (`hooks/usePort.ts`); a reload clears it and nothing about it is stored. Port-list and dataset import and persistence arrive in Chunk 11.

## Imported versions (Chunk 11; UNCONFIRMED PROPOSAL; written and read by the Regulation Center)
Three kinds, kept apart: `REGULATION` (a regulation dataset, `datasetId`), `PORTS` (a port list, `listId`) and, since Chunk 16, `AREAS` (an area boundary file, `setId`). Both go inside the normal store envelope `{v:1,t,d}`; `d` carries its own explicit format version (`VERSION_STORE_FORMAT = 1`). An unknown format version is a specific `UNSUPPORTED_FORMAT` error: not read, not changed, not repaired; there is no migration.
Keys (under the `eca-pilot:` prefix):
- `versions:<KIND>:index` - the only mutable record: `{ formatVersion, kind, versions: VersionMeta[], active: { <sourceId>: <versionKey> }, log: ActivationEvent[] }`.
- `versions:<KIND>:v:<versionKey>` - one per version, written once, never edited: `{ formatVersion, kind, key, raw }` where `raw` is the file exactly as supplied (parsed JSON). `versionKey = <sourceId>@<version>`.
`VersionMeta`: `key, kind, sourceId, version, publicationDate, isDemo (always false), importedAt, fileName | null, acceptedCount, rejectedCount, rejectedIds[], partial, oldestVerified | null`. `ActivationEvent`: `{ at, kind, sourceId, action: ACTIVATE | ROLLBACK | REMOVE, from | null, to | null }` (append-only; removing an INACTIVE version adds no line).
Rules: the file is parsed with the same strict parsers as bundled data every time it is read (so rejected records stay rejected and the same freshness rules apply); a DEMO-flagged file is never stored; the same key with identical content is `ALREADY_IMPORTED`, with different content `VERSION_CONFLICT` (never replaced); an import never activates; at most one active version per `sourceId`; production data is used only when exactly one `sourceId` is active (two = error); removing needs `{ confirmed: true }`. localStorage is the backend because imported files are capped at 1,000,000 characters; IndexedDB is deferred to Chunk 14 if real datasets prove larger. `store.clear()` ("Reset local data") also removes these keys.

UI facts (Chunk 11B): the Regulation Center writes these keys only through `versionActions` (`hooks/useData.ts`), never directly. The Port screen scope (DEMO | REAL) and the chosen port are NOT stored (session only, a reload clears them). Settings "Erase all local data" (`store.clear()`) removes every app key, including all imported versions and the activation history, and its confirmation text says so. Area boundary files (Chunk 16) are stored as kind `AREAS` versions with the same keys and rules; their confirmations are in `areas:confirmations`. The activation history records activations, roll backs and the removal of an ACTIVE version; removing an inactive version is not recorded.

## Changeover log (Chunk 13A format; UNCONFIRMED PROPOSAL; STORED since Chunk 13B)
Key `changeover-log` (under `eca-pilot:`), inside the normal store envelope `{v:1,t,d}`; `d = { schemaVersion: 1, entries: LogEntry[] }`, no other fields. At most 1000 entries (a full log refuses a new entry).
`LogEntry`: `id` (text, 1-64 chars, one line, unique), `createdAtMs` (epoch ms, required), `updatedAtMs` (epoch ms | null), `changeoverStartMs` / `changeoverEndMs` (epoch ms | null, end not before start), `startPosition` / `endPosition` (`{lat, lon}` | null, degrees), `quantity` (`{value > 0, unit m3|L|t|kg}` | null), `sulphurHighPercentMm` / `sulphurLowPercentMm` (0..100 | null), `fromTank` / `toTank` (`{name | null, grade hfo|vlsfo|mgo|other | null}` | null), `remarks` (non-blank text up to 2000 chars | null), `appContext` (`{predictedLatestStartMs | null, statusAtEntry | null, scope DEMO|REAL | null, flags[] of DEMO|MOCK|DERIVED|VERIFY, prefilled[] of entry field names}` | null). Every key must be present; `null` = not entered and is never 0. Times are UTC instants in 2000-2099; the app never guesses a ship's time zone. An entry needs at least one user-reported value. Unknown format version or unknown top-level field rejects the whole log; a damaged entry is reported by position and left out, never repaired. Written by `services/log/logStore.ts` only: the whole log on every add / edit / delete; never written while the stored log holds damaged entries (they would be lost) until a confirmed removal; never written when the stored value is corrupt or has another format version. Times are typed in UTC and stored as epoch ms; ids and times come from the screen.
The alert list is NOT this log (it is session-only). The older note that `changeover_log` / `gps_track` tables are planned is superseded for the log by this key-value format; no GPS track is stored.

## Storage backend, errors and caches (Chunk 14)
- Backend unchanged: `localStorage`, prefix `eca-pilot:`, envelope `{v:1, t, d}`; memory fallback only when reading is blocked (or writing fails and the app has nothing stored). No new key, no migration. IndexedDB is a proposal only (see `ARCHITECTURE.md`).
- `KeyValueStore.usage()` returns `{ items, characters }` over this app's own keys (key text + stored text). It is an approximate size, not bytes, and says nothing about free space.
- Errors: `StorageError.code` is `FULL`, `BLOCKED`, `CORRUPT` or `UNSUPPORTED_FORMAT`.
- Cache Storage (not part of the key-value store): one cache `eca-pilot-v<APP_VERSION>-<fingerprint>` holding the built files; older `eca-pilot-*` caches are deleted when a new worker activates. Erasing local data in Settings does not touch it.

## Area boundary files (Chunk 16 part A; UNCONFIRMED PROPOSAL)
Stored as kind `AREAS` imported versions (`versions:AREAS:index`, `versions:AREAS:v:<setId@version>`, `raw` = the file as supplied). Format `schemaVersion 2` (schema 1 is still read; `models/areaset.ts`, `services/areas/loader.ts`). Schema 2 adds the REQUIRED top-level field `"coverage": "COMPLETE" | "PARTIAL"` (exact, case-sensitive; anything else refuses the whole file). Schema 1 has no such field (a schema 1 file that carries it is refused) and is treated as PARTIAL by assumption, never COMPLETE. A PARTIAL set never produces OUTSIDE or NORMAL in the alert layer, also when confirmed. Changing only `coverage` in a file with the same `setId@version` is a VERSION_CONFLICT; GeoJSON positions are `[lon, lat]`:
`{ schemaVersion, setId, version, publicationDate, isDemo, coverage (schema 2 only), source: { name, reference, url | null, retrievedDate }, areas: [ { id, name, type, sourceReference, sourceDate, notes?, geometry: { type: "Polygon" | "MultiPolygon", coordinates } } ] }`
Rules: unknown fields are refused; `publicationDate`, `source.retrievedDate` and each `sourceDate` must be valid and not in the future; at least one area; ids unique; each geometry passes the strict area parser; ANY problem refuses the whole file (no partial import) and names the area; a DEMO-flagged file is never stored; the 1,000,000-character import cap applies. `VersionMeta.oldestVerified` holds the oldest per-area `sourceDate` (a source date, not a verification).
Key `areas:confirmations` (own format version `AREA_CONFIRMATIONS_FORMAT = 1`): `{ formatVersion, entries: [ { key, confirmedBy, confirmedAt, statement } ] }`, append-only, one entry per `setId@version`; `statement` is always the fixed text `AREA_CONFIRMATION_STATEMENT`. A version with no entry is UNVERIFIED. An unreadable list means nothing counts as confirmed. "Erase all local data" removes this key too.
