# ⚓ ECA Changeover Pilot
**SOx & NOx Regulatory Advisor + Fuel Changeover Timing Assistant**
*KNOW THE RULE. KNOW THE POSITION. KNOW WHEN TO ACT.*

Offline-first PWA (React + TypeScript + Vite) for onboard decision support.
> Decision-support and regulatory awareness tool only. NOT an official navigation system, ECDIS replacement, IMO/Flag-approved compliance system, substitute for the SMS or official nautical publications, or a guarantee of legal compliance.

## Run
```bash
npm install
npm run dev          # development
npm test             # unit tests (tsx tests/run.ts)
npm run build        # tsc --noEmit && vite build  (official build)
npm run preview
```
`npm run build` also runs `scripts/make-sw.mjs`, which writes `dist/sw.js` (cache name from the app version, precache list of every built file). Deploy the whole `dist/` folder. An update shows a "new version ready, reload" notice and waits for the user. See `docs/OFFLINE_AUDIT.md` for what was and was not tested offline.

**Sandbox fallback (no npm registry):** `npm run build:offline` builds with esbuild only (no type-check). Needs esbuild from `node_modules`, `ESBUILD_MODULE`, or a global `tsx` install.

Browser smoke tests (optional, need global Playwright; `smoke-log` also needs poppler `pdfinfo` / `pdftotext`): `npm run build:offline && node tests/smoke-vessel.mjs && node tests/smoke-calculator.mjs && node tests/smoke-regulations.mjs && node tests/smoke-geo.mjs && node tests/smoke-map.mjs && node tests/smoke-gps.mjs && node tests/smoke-prediction.mjs && node tests/smoke-sox.mjs && node tests/smoke-noxpm.mjs && node tests/smoke-port.mjs && node tests/smoke-versions.mjs && node tests/smoke-alerts.mjs && node tests/smoke-log.mjs && node tests/smoke-offline.mjs && node tests/smoke-wording.mjs && node tests/smoke-a11y.mjs && node tests/smoke-subpath.mjs && node tests/smoke-a11y.mjs && node tests/smoke-areas.mjs`. `smoke-offline`, `smoke-wording` and `smoke-subpath` need poppler as well. ## Deploy
Build with `npm install && npm run build` and publish the WHOLE `dist/` folder as static files. There is no server code and the app makes no network request of its own.
- **HTTPS** is required for the service worker and for geolocation (`localhost` also works for testing). Without HTTPS the app still runs but does not install an offline copy and device GPS is unavailable.
- **`sw.js`**: serve it so that browsers re-check it, for example `Cache-Control: no-cache` (a long-lived cache on `sw.js` is expected to delay the "new version ready" notice; this was not tested against a real host). The worker precaches every built file by its URL and its cache name contains a fingerprint of the files, so a rebuild with the same version number but different files is found as an update (tested in `tests/smoke-subpath.mjs`). Still bump the version for every release.
- **Sub-path**: `base: "./"` and the relative worker / manifest paths let `dist/` sit under any folder (for example `https://host/eca/`). This was tested with a plain static server under `/eca/`; it was not tested on a real host.
- **Same-origin neighbours**: the worker only handles requests inside its own folder; another app on the same origin must use another folder.
- **Updates**: a new version installs in the background and waits; the user presses "Reload now". Nothing is replaced under a running page.
- **Config**: copy `.env.example` to `.env`; never commit keys. No key is needed today.
- **Before use on board**: `docs/RELEASE_CHECKLIST.md` (what was tested, what was not, what only you can supply). The app ships with NO real regulation, area or port data.

## Publishing on GitHub

1. Create an empty repository and upload the project (see the batch instructions that came with the ZIP, or use `git`).
2. In the repository: Settings > Pages > Source = "GitHub Actions".
3. Every push to `main` runs `.github/workflows/pages.yml`: `npm install`, `npm test`, `npm run build` (this runs the full TypeScript check, which needs the React types from `npm install`), then publishes `dist/` to `https://<user>.github.io/<repo>/`. GitHub Pages is HTTPS, so device GPS and the service worker work there.
4. `dist/` is not committed (see `.gitignore`); the workflow builds it. No license file is included: choose one yourself before making the repository public. The app bundles no real regulatory data, but `boundaries/source/` holds coordinate lines read from the publishers' PDFs; consider a private repository, or check the publishers' terms, before making it public.
